যে টেকনিশিয়ানরা ফিঙ্গারপ্রিন্ট, ফেস বা RFID ডিভাইস ইনস্টল করেন তাদের জন্য এই গাইড। শেষ হলে ডিভাইসের প্রতিটি পাঞ্চ স্বয়ংক্রিয়ভাবে eEdu-তে চলে আসবে — কোনো কম্পিউটার চালু রেখে দিতে হবে না।

## শুরু করার আগে যা থাকা দরকার

- eEdu-তে **ওনার বা শিক্ষক** অ্যাকাউন্ট দিয়ে লগইন।
- ডিভাইসটি চালু এবং স্কুলের নেটওয়ার্ক/ইন্টারনেটের সাথে যুক্ত।
- ডিভাইসের ঘড়িতে সঠিক বাংলাদেশ সময় (Asia/Dhaka)।

---

## ধাপ ১ — ডিভাইসটি eEdu-তে রেজিস্টার করুন

1. **`ড্যাশবোর্ড → শিক্ষার্থী → উপস্থিতি`** খুলুন।
2. **সেটিংস** ট্যাবে গিয়ে **ডিভাইস** অংশটি দেখুন।
3. **ডিভাইস যোগ করুন** চাপুন এবং ফর্মটি পূরণ করুন:

> **স্ক্রিনশট প্লেসহোল্ডার:** *"ডিভাইস যোগ করুন" ফর্মটি — মডেল, ডিভাইসের ধরন, অবস্থান ও টার্গেট গ্রুপ ক্ষেত্রসহ।*

| ক্ষেত্র | কী লিখবেন |
| --- | --- |
| **মডেল** | ডিভাইসের মডেল, যেমন `ZK9500` |
| **ডিভাইসের ধরন** | **ফিঙ্গারপ্রিন্ট** / **ফেস** / **RFID কার্ড** — এক বা একাধিক |
| **অবস্থান** | ডিভাইসটি কোথায় বসছে, যেমন `মেইন গেট`, `স্টাফ প্রবেশপথ` |
| **টার্গেট গ্রুপ** | **শিক্ষার্থী**, **শিক্ষক**, বা উভয় — কারা এই ডিভাইস ব্যবহার করবেন |

4. **সংরক্ষণ করুন** চাপুন।

একটি কনফার্মেশন বক্স আসবে যেখানে দুটি গুরুত্বপূর্ণ মান থাকবে — **এখনই দুটি কপি করে রাখুন**:

- **ডিভাইস সিক্রেট কী** — ৩২ অক্ষরের একটি কী। এটিই ডিভাইসের পাসওয়ার্ড। এটি **শুধু একবার** দেখানো হয়, তাই ভালো জায়গায় (পাসওয়ার্ড ম্যানেজার বা ফাইলে) সংরক্ষণ করুন।
- **ডিভাইস সিরিয়াল** — সাধারণত শুরুতে খালি থাকে; প্রথম পাঞ্চ পাঠানোর সময় eEdu নিজে থেকেই এটি শনাক্ত করে নেয়।

> **স্ক্রিনশট প্লেসহোল্ডার:** *সফল সংযোগ ডায়ালগ — ডিভাইস সিক্রেট কী, "কপি" বাটন ও সুরক্ষিত মোডের নোটসহ।*

> [!WARNING]
> ডিভাইস সিক্রেট কী পাসওয়ার্ডের মতোই সুরক্ষিত রাখুন। গ্রুপ চ্যাটে শেয়ার করবেন না; সন্দেহ হলে একই ডিভাইস তালিকা থেকে **কী পরিবর্তন (Rotate)** করুন — পুরনো কী সঙ্গে সঙ্গেই অচল হয়ে যাবে।

## ধাপ ২ — ডিভাইসটিকে eEdu-র সাথে কথা বলতে কনফিগার করুন

ডিভাইসের নিজস্ব সেটিংস খুলুন (সাধারণত ডিভাইসের IP ঠিকানায় ব্রাউজার চালিয়ে, অথবা LCD মেনু থেকে)। এগুলো একদম নির্দিষ্টভাবে সেট করুন:

| ডিভাইস সেটিং | যে মান দেবেন |
| --- | --- |
| Communication mode (যোগাযোগ মোড) | **TCP/IP** |
| Attendance mode (উপস্থিতি মোড) | **Push** (Command বা Cloud মোডও বলা হয়) |
| Server address / host (সার্ভার ঠিকানা) | `api.eedu.bd` |
| Port (পোর্ট) | `443` |
| **Server URL / Push URL** | `https://api.eedu.bd/api/v1/devices/attendance/ingest` |
| **ডিভাইস সিক্রেট কী** | ধাপ ১-এর ৩২ অক্ষরের কী |
| ডিভাইসের ঘড়ি | **Asia/Dhaka (UTC +6)** এবং সম্ভব হলে স্বয়ংক্রিয় সময় সিঙ্ক (NTP) চালু |
| অফলাইন বাফার | **চালু** (নেটওয়ার্ক না থাকলে রেকর্ড ডিভাইসে জমা থাকবে) |

> [!NOTE]
> eEdu ডিভাইসের জন্য **HTTPS (পোর্ট 443)** ব্যবহার করে, তাই আপনার ফায়ারওয়াল/রাউটারে শুধু আউটবাউন্ড ওয়েব ট্রাফিক অনুমোদিত হলে হবে। **পাবলিক IP, পোর্ট ফরওয়ার্ডিং বা স্ট্যাটিক IP লাগবে না**।

> **ডায়াগ্রাম প্লেসহোল্ডার:** *সহজ নেটওয়ার্ক ছবি — স্কুলের গেটের ডিভাইস → "HTTPS আউটবাউন্ড" তীরচিহ্ন → ক্লাউডের eEdu সার্ভার → "উপস্থিতি রেকর্ড" তীরচিহ্ন।*

### ZKTeco/ADMS-নির্দিষ্ট সেটিংস

আপনার ডিভাইস যদি **ADMS** (ZKTeco-র ডেস্কটপ টুল) ব্যবহার করে:

1. ADMS-এ ডিভাইস এন্ট্রি তৈরি করুন, উপরের সার্ভার তথ্যগুলোই দিন।
2. ADMS ছাড়া চলা ডিভাইসের জন্য (স্ট্যান্ডঅ্যালোন পুশ মোড) সরাসরি ডিভাইসে পুশ URL ও সিক্রেট কী বসিয়ে দিলেই হয় — ADMS লাগবে না।

যেভাবেই হোক, ডিভাইসটিকে অবশ্যই পাঞ্চ তথ্য (ইউজার আইডি + সময়) উপরের পুশ URL-এ সিক্রেট কীসহ পাঠাতে হবে। আপনার বিতরণকারী যদি আলাদা কোনো কানেক্টর প্রোগ্রাম দেয়, তবে সেটিকেও একই ঠিকানায় পাঞ্চ পাঠাতে বলুন।

## ধাপ ৩ — সংযোগ পরীক্ষা করুন

1. ডিভাইসে একটি **পরিচিত ব্যক্তির** পাঞ্চ দিন (যেকোনো নিবন্ধিত ফিঙ্গারপ্রিন্ট বা কার্ড)।
2. eEdu-তে **`ড্যাশবোর্ড → শিক্ষার্থী → উপস্থিতি → সেটিংস → ডিভাইস`** খুলুন।
3. ডিভাইসের **পাঞ্চ লগ** খুলুন — পাঞ্চটি **প্রসেসড** (Processed) স্ট্যাটাস ও ঠিক ব্যক্তির নামে দেখা যাবে।

> **স্ক্রিনশট প্লেসহোল্ডার:** *ডিভাইস তালিকা — স্ট্যাটাস "Active" ও "Pending" বাফার সংখ্যা ০।*

প্রথম পাঞ্চ সফল হলে **সিরিয়াল স্বয়ংক্রিয়ভাবে ধরা পড়ে** এবং ডিভাইসের স্ট্যাটাস **Active** হয়।

---

## ধাপ ৪ — ডিভাইসের ঘড়ি সেট করুন (খুব গুরুত্বপূর্ণ)

পাঞ্চের সময় ভুল মনে হচ্ছে বা আজ/আগামীকালের দিনে পড়ছে:

1. ডিভাইসে **Clock / Date Time** সেটিংস খুঁজুন।
2. টাইমজোন **Asia/Dhaka (GMT+6)** করুন।
3. সম্ভব হলে **Time Sync / NTP** চালু করুন।
4. আবার পাঞ্চ দিয়ে পরীক্ষা করুন।

eEdu ডিভাইসের সময় Dhaka সময়ে পড়ে। ডিভাইসের ঘড়ি ভুল থাকাই "ভুল দিনে উপস্থিতি" দেখানোর সবচেয়ে বড় কারণ।

## শেষ — এরপর যা হয়

এখন থেকে পাঞ্চগুলো স্বয়ংক্রিয়ভাবে চলবে:

- শিক্ষার্থীদের আপনার ক্লাসের সময়-নিয়ম অনুযায়ী **উপস্থিত** বা **বিলম্বিত** (Late) চিহ্নিত করা হয় (`ড্যাশবোর্ড → শিক্ষার্থী → উপস্থিতি → সেটিংস`)।
- শিক্ষকদের ইন/আউট সময় ধরা হয়, যা **ওভারটাইম আওয়ার** গণনাতেও কাজে লাগে।
- ইন্টারনেট বিচ্ছিন্ন হলে ডিভাইস **বাফারে** পাঞ্চ জমা রাখে এবং সংযোগ ফিরলে নিজে থেকেই পাঠিয়ে দেয়।

পরের গাইড: **[মেশিন ইউজার আইডি দিয়ে শিক্ষার্থী ও শিক্ষক চেনানো](/bn/docs/hardware-guide/user-id-mapping)** — এতেই প্রতিটি পাঞ্চ সঠিক মানুষের নামে জমা হয়।

> [!TIP]
> ডিভাইসের ঘড়ি NTP-সিঙ্কড রাখুন এবং ডিভাইস সিক্রেট কী পাসওয়ার্ড ম্যানেজারে সংরক্ষণ করুন — এই দুটি অভ্যাসই ৯০% অ্যাটেনডেন্স সাপোর্ট কল বাঁচিয়ে দেয়।
