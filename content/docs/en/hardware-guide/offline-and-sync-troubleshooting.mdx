If punches don't appear in eEdu, work down this list.

---

## 1. Is the device online?

On the device, open **COMM / Network** and check it has an IP address.

- **No IP** → check the LAN cable / Wi-Fi password, then reboot.
- **Has IP but no internet** → on another device at school, open any website. If that fails, fix the school internet first.

<Figure src="/images/docs/biometric-devices.webp" alt="Device to eEdu network path" />

---

## 2. Is it pointing at eEdu?

| Setting | Must be |
| --- | --- |
| Attendance mode | **Push / Cloud** |
| Server / Push URL | `https://api.eedu.bd/api/v1/devices/attendance/ingest` |
| Port | `443` |
| Secret key | matches eEdu |
| Request signing | Device sends `x-device-timestamp` (ms) and a valid `x-device-signature` (see the device guide) |

> [!NOTE]
> Re-check the push URL and secret key in `Dashboard → Students → Attendance → Settings` (Devices section). A single wrong character stops all punches.

---

## 3. Is the time right?

Wrong time = wrong day/late status.

1. Device → **Clock** → timezone **Asia/Dhaka (GMT+6)**.
2. Turn on **NTP / time sync**, save and reboot.

---

## 4. Is the eEdu side healthy?

1. Open **`Dashboard → Students → Attendance → Settings`** (Devices section).
2. Check **status** (Active?) and the **Pending buffer** count — a non-zero buffer means eEdu is still catching up, so wait a moment.
3. Open **Punch Logs**: for what each status means (listed / Error / missing), see [Attendance: Logs Won't Sync](/en/docs/troubleshooting/attendance-sync-issues) §1.

---

## Still stuck?

| Symptom | Likely cause |
| --- | --- |
| Nothing at all | Wrong push URL/key, or device offline |
| Some punches missing | Network drop; device buffers and re-sends when back |
| Wrong day/time | Device clock/timezone |

**Wrong person** or an **Error** status is a mapping question — handled in [Attendance: Logs Won't Sync](/en/docs/troubleshooting/attendance-sync-issues) §4.

If it still fails, contact eEdu support with the device **model, serial and status**.
