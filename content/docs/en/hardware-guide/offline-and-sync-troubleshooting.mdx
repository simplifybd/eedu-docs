---
title: Fixing Offline & Sync Problems
description: Diagnose a device that is offline, not sending punches, or showing the wrong time.
---

<Figure src="/images/docs/network.jpg" alt="A network rack with a router and switch" />

If punches don't appear in eEdu, work down this list.

---

## 1. Is the device online?

On the device, open **COMM / Network** and check it has an IP address.

- **No IP** → check the LAN cable / Wi-Fi password, then reboot.
- **Has IP but no internet** → on another device at school, open any website. If that fails, fix the school internet first.

<Figure src="/images/docs/biometric_devices.webp" alt="Device to eEdu network path" />

---

## 2. Is it pointing at eEdu?

| Setting | Must be |
| --- | --- |
| Attendance mode | **Push / Cloud** |
| Server / Push URL | `https://api.eedu.bd/api/v1/devices/attendance/ingest` |
| Port | `443` |
| Secret key | matches eEdu |

> [!NOTE]
> Re-check the push URL and secret key in `Dashboard → Students → Attendance → Settings → Devices`. A single wrong character stops all punches.

<YouTube id="JBWeKcBDZNI" title="ZKTeco device full configuration" />

---

## 3. Is the time right?

Wrong time = wrong day/late status.

1. Device → **Clock** → timezone **Asia/Dhaka (GMT+6)**.
2. Turn on **NTP / time sync**, save and reboot.

---

## 4. Is the eEdu side healthy?

1. Open **`Dashboard → Students → Attendance → Settings → Devices`**.
2. Check **status** (Active?) and the **Pending buffer** count.
3. Open **Punch Logs**:
   - **New/queued** → eEdu is catching up; wait a moment.
   - **Error** → usually a key or mapping issue.

---

## Still stuck?

| Symptom | Likely cause |
| --- | --- |
| Nothing at all | Wrong push URL/key, or device offline |
| Some punches missing | Network drop; device buffers and re-sends when back |
| Wrong person | User ID mismatch — see [User ID mapping](/docs/hardware-guide/user-id-mapping) |
| Wrong day/time | Device clock/timezone |

If it still fails, contact eEdu support with the device **model, serial and status**.
