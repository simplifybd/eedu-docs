title: Connect an Attendance Device
description: Connect a fingerprint, face or RFID attendance device that supports eEdu's signed push so every punch arrives automatically.
---

<Figure src="/images/docs/biometric-devices.webp" alt="A biometric device sending punches to eEdu over HTTPS" />

**Before you start:** an owner/teacher login, a powered device on the network, and the device clock set to **Asia/Dhaka**.

---

## 1. Register the device in eEdu

1. Go to **`Dashboard → Students → Attendance`** → **Settings** tab → **Devices**.
2. Click **Add Device** and fill in:

| Field | What to enter |
| --- | --- |
| **Model** | e.g. `ZK9500` |
| **Device type** | Fingerprint / Face / RFID card |
| **Location** | e.g. `Main gate` |
| **Target group** | Students, Teachers, or both |

3. Click **Save** and **copy the Device Secret Key now** — it is shown only once.

> [!WARNING]
> The Device Secret Key is the device's password. Keep it in a password manager; rotate it from the same screen if it ever leaks.

---

## 2. Point the device at eEdu

Open the device's settings (browser page or LCD menu) and set:

| Device setting | Value |
| --- | --- |
| Communication mode | **TCP/IP** |
| Attendance mode | **Push** (Cloud) |
| Server address | `api.eedu.bd` · Port `443` |
| **Push URL** | `https://api.eedu.bd/api/v1/devices/attendance/ingest` |
| **Device Secret Key** | the key from step 1 |
| Clock | **Asia/Dhaka (UTC +6)**, NTP on |
| Offline buffer | **On** |

### Does your device support eEdu?

eEdu only accepts punches that are **signed by the device itself** — a security check the device firmware performs, not something your staff has to configure.

- A device that cannot sign its own requests is **not supported**. Confirm this with your supplier **before you buy**.
- Device vendors and integrators can request the full technical specification from eEdu.

**ZKTeco / ADMS (iClock) devices:** the vendor's native push format is **not** supported directly, because it cannot sign requests. Such devices need a gateway — contact eEdu support before installation.

---

## 3. Test the connection

1. Punch a **known user** on the device.
2. Open **`Dashboard → Students → Attendance → Settings`** (Devices section) → **Punch Logs**.
3. You should see the punch as **Processed** with the right name. The device turns **Active** and its Serial is captured automatically.

> [!NOTE]
> The video below covers the device-side setup (network, time, user enrolment). For ZKTeco models that only speak the native ADMS/iClock push, arrange the gateway with eEdu support **first** — otherwise the punch never reaches us.

## 4. Set the clock (very important)

Wrong times are the #1 cause of “wrong day” attendance.

1. Device settings → **Clock / Date Time**.
2. Timezone **Asia/Dhaka (GMT+6)** and turn on **NTP / time sync**.
3. Punch again to confirm.

---

## Done

Students are marked **Present** or **Late** by your class timing rules; teacher check-ins feed **overtime** for payroll. If the internet drops, the device buffers and re-sends.
