title: Connecting Your Attendance Device to the eEdu Server
description: Configure a ZKTeco, RFID or face device to send punches to eEdu — server address, port, push mode and device secret key.
---

This guide is for the technician installing an attendance terminal (fingerprint, face or RFID card). When finished, every punch on the device appears in eEdu automatically — no computer needs to stay on.

## What you need before you start

- Log in to eEdu with an **owner or teacher** account.
- The device is powered on and connected to your school network / the internet.
- The device's clock shows the correct Bangladesh time (`Asia/Dhaka`).

---

## Step 1 — Register the device in eEdu

1. Go to **`Dashboard → Students → Attendance`**.
2. Open the **Settings** tab, then find the **Devices** section.
3. Click **Add Device** and fill in the form:

> **Screenshot placeholder:** *The "Add Device" form showing Model, Device Type, Location and Target Group fields.*

| Field | What to enter |
| --- | --- |
| **Model** | The device model, e.g. `ZK9500` |
| **Device type** | One or more of **Fingerprint** / **Face** / **RFID card** |
| **Location** | Where it sits, e.g. `Main gate`, `Staff entrance` |
| **Target group** | **Students**, **Teachers**, or both — who this device tracks |

4. Click **Save**.

A confirmation box appears with two important values — **copy both now**:

- **Device Secret Key** — a 32-character key. This is the device's password. It is shown **only once**, so store it safely (password manager or your file).
- **Device Serial** — normally empty at first; eEdu detects it automatically the first time the device sends a punch.

> **Screenshot placeholder:** *The success dialog showing the Device Secret Key with a "Copy" button and the HMAC/secure-mode note.*

> [!WARNING]
> The Device Secret Key is like a password. Don't share it in group chats, and if you ever suspect it leaked, rotate it from the same Devices screen — the old key stops working immediately.

---

## Step 2 — Configure the device to talk to eEdu

Open the **device's own settings** (usually a web browser page on the device's IP address, or the LCD menu). Set these exactly:

| Device setting | Value to use |
| --- | --- |
| Communication mode | **TCP/IP** |
| Attendance mode | **Push** (also called Command or Cloud mode) |
| Server address / host | `api.eedu.bd` |
| Port | `443` |
| **Server URL / Push URL** | `https://api.eedu.bd/api/v1/devices/attendance/ingest` |
| **Device Secret Key** | the 32-character key from Step 1 |
| Device clock | **Asia/Dhaka (UTC +6)**, with automatic time sync (NTP) switched on, if available |
| Offline buffer | **On** (records store locally when the network is down) |

> [!NOTE]
> eEdu uses **HTTPS (port 443)** for device connections, so your firewall/router only needs to allow outbound web traffic. You do **not** need a public IP, a port-forwarding rule, or a static IP for the device.

> **Diagram placeholder:** *Simple network drawing — Device at the school gate → arrow labeled "HTTPS outbound" → eEdu server in the cloud → arrow back labelled "attendance records".*

### ZKTeco/ADMS-specific settings

If your device uses **ADMS** (the ZKTeco desktop tool):

1. In ADMS, create the device entry with the same server details above.
2. For devices managed **without** ADMS (standalone push mode), you can configure the push URL and secret key directly on the device and skip ADMS entirely.

Either way, the device must end up sending punches to the **push URL** with its **secret key**. If your distributor provides a small connector program instead, ask them to send the same punch data (user ID + time) to the address above.

---

## Step 3 — Test the connection

1. On the device, punch a **known user** (any enrolled fingerprint or card).
2. In eEdu, go to **`Dashboard → Students → Attendance → Settings → Devices`**.
3. Open the device's **Punch Logs**. You should see the punch with status **Processed** and the correct person's name.

> **Screenshot placeholder:** *Device list showing a device with status "Active" and a healthy Pending (buffer) count of 0.*

If the first punch worked, the device **Serial is captured automatically** and the device status changes to **Active**.

---

## Step 4 — Set the device clock (very important)

If punches arrive at the wrong time or get marked as tomorrow/yesterday:

1. On the device, find **Clock / Date Time** settings.
2. Set timezone to **Asia/Dhaka (GMT+6)**.
3. Enable **Time Sync / NTP** if available.
4. Re-test a punch.

eEdu reads device times in Dhaka time. A wrong device clock is the most common cause of "wrong day" attendance.

---

## Done — what happens next

From now on punches flow automatically:

- Students are marked **Present** or **Late** based on your class timing rules (`Dashboard → Students → Attendance → Settings`).
- Teachers are marked with their check-in/check-out, which also feeds **overtime hours** for payroll.
- If the internet drops, the device **buffers** punches and sends them automatically when the connection returns.

Next guide: **[Map machine user IDs to students & teachers](/docs/hardware-guide/user-id-mapping)** — this is what makes each punch match the right person.

> [!TIP]
> Keep the device clock NTP-synced and the Device Secret Key in your password manager — those two habits prevent 90% of attendance support calls.
